## 开篇:为什么中断要单独拎出来讲

§1 的隔离栈在赶各种噪音源:别的用户线程、内核线程、周期 tick、RCU 回调、中断。其中**中断是唯一一个不理会调度器优先级的**。

你把线程设成 `SCHED_FIFO` 99(系统里能给的最高实时优先级)、绑死在核上、`nohz_full` + `rcu_nocbs` 全套配好——一个网卡硬中断到来时,CPU 硬件照样在你的任意一条指令中间停下,跳去执行内核的中断处理函数。调度器全程不知情。`chrt`、nice 值、cgroup 权重,对硬中断**一律无效**,因为硬中断不是"一个更高优先级的任务",它是坐在整个调度器**之上**的硬件机制。

结论:**对硬中断,你没有"抢占赢它"这个选项,只有"把它路由到别的核去"。** 这一篇讲的就是这件事怎么做、怎么验证,以及三个会让你白忙的坑。

## 一、一次中断对热线程做了什么(补)

一个 IRQ 到来,当前核会:停下正在执行的指令流 → 保存现场 → 跳到内核中断处理函数 → 处理完恢复现场继续。

代价**不止**处理函数那几百纳秒的运行时间,真正贵的是副作用:

- 流水线清空,重填几十个周期;
- 处理函数的代码 + 数据把你的 L1i / L1d 挤掉一部分,回来后前几百条指令都在 miss;
- 分支预测器里养熟的历史被污染;
- 可能顶掉一两个 TLB 条目。

单次看,和一次线程迁移是同种伤害,量级小一点。关键在**频率**:一个没配置过、正在收行情的核,每秒吃几千次这种中断(网卡每收一批包一次)。累积起来就是延迟直方图上那条抬起来的尾巴——而且形状是"高频小尖峰",和 NUMA 那种"整体基线抬高"、C-state 那种"刚空闲过才发作的大尖峰"又不一样。

## 二、上半部 / 下半部:最关键的心智模型(补)

源笔记完全没提这个结构,但不理解它,后面绑定的行为讲不通。

Linux 把中断处理**切成两截**:

**上半部(top half / 硬中断 hardirq)** —— 在**关中断**的状态下运行,所以必须极短。只做三件事:

1. 应答设备(让它撤下 IRQ 线,否则一直触发);
2. 拿走最少量信息(比如收一个 DMA 描述符);
3. **登记一个"稍后要干的活"**,然后返回。

**下半部(bottom half / 软中断 softirq)** —— 真正的重活:遍历网卡环形缓冲区、构造 `sk_buff`、把包送进协议栈。放在这里。

**为什么拆?** 上半部关中断,窗口越短越好。重活拖在里面会把整个核的中断响应能力压死,也会拉长别的中断的延迟。

### 下半部在哪个核跑

- **默认:就在刚才吃硬中断的那个核上**,硬中断返回后立刻接着跑(`irq_exit()` 尾部,仍在中断上下文)。
- **溢出时:** 如果包速太高、软中断堆积比处理快,内核把它甩给一个**每核的内核线程 `ksoftirqd/N`**。这个线程是普通 `SCHED_OTHER`,回到用户态调度里跟你的线程抢 CPU。

### 这对绑定意味着什么

> 你把 IRQ 128 的亲和性绑到 core 2 —— **硬中断和它的软中断一起被引到 core 2**。而 `ksoftirqd/2` 只有在 core 2 吃这些硬中断时才有活。所以"把网卡 IRQ 从热点核绑走"这**一个动作**,同时让热点核上的 `ksoftirqd` 一直睡 —— 这正是 §1 说的"掐掉活儿来源,饿死 per-CPU kthread"。

## 三、实操三步:找 → 绑 → 验

### 第 1 步:确认中断是瓶颈

`mpstat -P ALL 1`,逐核看两列:

| 列 | 含义 | 高说明什么 |
|---|---|---|
| `%irq` | 硬中断占用时间 | 这个核是硬中断汇集点 |
| `%soft` | 软中断占用时间 | 软中断处理压力大(多半 `NET_RX`) |

`top` 里 `ksoftirqd/N` 常驻高 CPU → 软中断已溢出到线程。

### 第 2 步:找到 IRQ 号

`cat /proc/interrupts`:行是 IRQ,中间每列是**一个 CPU 的累计计数**,最后一列是设备/处理函数名。多队列网卡会看到 `eth0-rx-0`、`eth0-rx-1`……每队列一个独立 IRQ。

负载下看它当前落在哪个核:

```bash
watch -n1 'grep -E "eth0|130:" /proc/interrupts'   # 看哪个核的计数在涨
```

### 第 3 步:绑

```bash
echo 2   > /proc/irq/128/smp_affinity_list    # 绑到 core 2
echo 0-1 > /proc/irq/128/smp_affinity_list    # 绑到 core 0-1
```

用 `smp_affinity_list`(CPU 编号列表)而不是 `smp_affinity`(十六进制位掩码):core 37 的掩码要自己算 `0x2000000000`,容易错;列表直接写 `37`。改动在**下一次中断**时生效。

### 第 4 步:验(两个信号同时看)

- `/proc/interrupts` 里这个 IRQ 的计数,**只在绑定的核上涨**,其它核冻住;
- `mpstat` 里热点核的 `%irq` / `%soft` **掉到 ≈ 0**。

两个都满足才算成功。只看计数会漏——比如计数绑对了但 `%soft` 还高,说明软中断从别的源头来。

## 四、三个让你白忙的坑

### 坑一:managed IRQ,你根本写不动(补)

现代驱动(NVMe、很多高速网卡)用 `pci_alloc_irq_vectors_affinity` 申请中断,这类 IRQ 的亲和性是**内核托管的**——内核按队列数自动摊到各核。你 `echo` 到它的 `smp_affinity` 会直接返回 **`-EIO`**(写失败)。

对付它:驱动/固件层减少队列数,或用 `isolcpus=managed_irq` 让内核托管时避开隔离核(见坑三),或上内核旁路根本不走这条路。

### 坑二:irqbalance 会把手动绑定冲掉

`irqbalance` 是用户态守护进程,默认在跑,每 ~10 秒根据负载重新分配**所有** IRQ 的亲和性。你手动 `echo` 完,十几秒后它改回去。

想手动控制中断,第一件事:

```bash
systemctl stop irqbalance && systemctl disable irqbalance
```

然后所有 IRQ 布局用开机脚本 / systemd unit 静态设死。(想保留 irqbalance 又护住几个核:`IRQBALANCE_BANNED_CPUS` / `--banirq`;但 HFT 一般直接杀,不留活口。)

### 坑三:`isolcpus` 不管中断路由

最容易想当然的一个。`isolcpus=8-15` 只把这些核从**调度器**摘出去,**完全不动 IRQ 的亲和性掩码**。刚被隔离的核照样可能是设备中断的默认投递目标。

必须**另外**做,三个一起上:

| 手段 | 作用 |
|---|---|
| `irqaffinity=0,1`(启动参数) | 设**所有** IRQ 的默认亲和掩码为 core 0/1 |
| 逐个 `echo .../smp_affinity_list` | 对具体高频 IRQ 精细绑定 |
| `isolcpus=managed_irq,8-15` | 内核给 managed IRQ 自动派队列时避开 8-15(不管非托管的,也不追溯) |

## 五、NUMA 与多队列

### NUMA

网卡插在某个 PCIe 槽,物理连到某一个 socket。包 DMA 进内存、触发中断——如果在**另一个 socket** 的核上处理,描述符访问要过 UPI,软中断构造 `sk_buff` 也在远端内存里建。

网卡 IRQ 要绑到**网卡自己所在 NUMA 节点**的核:

```bash
cat /sys/class/net/eth0/device/numa_node   # 网卡在哪个节点(-1 = 单路或没暴露)
```

这条和 §1 的"热点核放网卡所在节点"是同一个约束的两头。

### 多队列 / RSS

10/25/100G 网卡有多个硬件 RX 队列,RSS 按流哈希打散到各队列,每队列一个 IRQ。

- **默认策略:** 队列 IRQ 摊到很多核,换吞吐。
- **HFT 常反着来:** 承载你那条行情组播的**那一个队列**的 IRQ,单独钉到一个管家核;其余队列关掉或绑别处。
- **终局:** Solarflare onload / DPDK **内核旁路** —— 网卡直接把包投到用户态,热路径上根本没有 IRQ。§3 讲的是还走内核那版。

## 六、和整体的连接

`/proc/interrupts` 里还有这些行,是**每核私有、不能绑走**的:

| 缩写 | 是什么 | 能压吗 |
|---|---|---|
| `LOC` | 本地 APIC 时钟中断 | `nohz_full` 压到 ~1Hz |
| `RES` | 重调度 IPI | 减少跨核唤醒 |
| `CAL` | 函数调用 IPI | —— |
| `TLB` | TLB shootdown IPI | 别和别的进程共享地址空间做 `munmap`/`mprotect` |

这些就是 §1 说的"隔离残渣"——`cyclictest` 测出来的地板,有一部分是这些拆不掉的中断。

## 附一:自检题与你的答案

**Q1. FIFO-99 的忙轮询线程绑死 core 3、`nohz_full`/`rcu_nocbs` 全配,`cyclictest` 仍每秒抓到几十个 5–15µs 毛刺,怀疑网卡中断。为什么 FIFO-99 救不了?压制手段两个,各作用在什么层面?**

> 你的答(2026-09-09):SCHED_FIFO 只是"软件调度器"的规则,网卡中断是"物理硬件"的电信号。手段:①中断路由重定向,把网卡 IRQ 强制绑到管家核 —— 中断控制器 + 内核路由层;②内核旁路 —— 硬件与驱动层。
>
> 评:**满分**。两个手段两个层面都对。锐化一句:调度器只决定"哪个**可运行任务**拿 CPU",中断不是任务,是 CPU 被本地 APIC 直接向量到处理函数,发生在调度器代码运行之前;FIFO-99 是"赢过别的线程",它不参与和中断的竞争。补一个区分——两个手段**性质不同**:中断路由是把成本**搬走**(管家核替 core 3 挨这一下,面试追问"绑走之后中断去哪了"要能答);内核旁路是把 IRQ **消掉**(NIC 直接 DMA 到用户态 ring,热路径上根本不产生中断)。
>
> 参考骨架:硬中断是 CPU 硬件机制,在关中断状态下由 CPU 直接跳转执行,**根本不经过调度器**,所以任何调度优先级(FIFO-99 也好)都无意义。两个手段:①**中断亲和性**(`/proc/irq/N/smp_affinity` + `irqaffinity=` 默认掩码)——把硬中断和它的软中断一起路由到管家核,作用在"中断投递目标"这一层;②**内核旁路**(DPDK / onload)——让网卡直接 DMA 到用户态,热路径上不产生 IRQ,作用在"数据通路是否进内核"这一层。前者是缓解,后者是消除。

**Q2. `%soft` 常年 8–12% 在 core 3,`ksoftirqd/3` 也在吃 CPU,单队列网卡 IRQ 130。完整排查 + 处理,并解释为什么"绑 IRQ 130 到 core 0"一个动作能同时摁下 `%soft` 和 `ksoftirqd/3`。**

> 你的答(2026-09-09):硬中断 130 投递到 core 0 后不再投递到 core 3;core 0 执行 ISR,触发 core 0 本地的 NET_RX_SOFTIRQ,不跨核触发 core 3;硬中断软中断都在 core 0 → NAPI 轮询和 budget 消耗全在 core 0,溢出被唤醒的也是 `ksoftirqd/0`。
>
> 评:"**为什么一个动作两个都掉**"这部分**满分** —— 还带出了 NAPI 和 softirq budget(正文没细讲),方向完全对。但 Q2 问的是"**完整排查 + 处理**",这半题没答。补:
> - 排查:`watch -n1 'grep -E "130:|CPU" /proc/interrupts'`(计数在 core 3 涨)→ `cat /proc/softirqs`(NET_RX 在 core 3 列是大头)→ `mpstat -P ALL 1`(core 3 %soft 高)→ `systemctl is-active irqbalance` → `echo 0 > /proc/irq/130/smp_affinity` 试写(`-EIO` = managed IRQ)。
> - 处理(**顺序重要**):① 先 `systemctl stop && disable irqbalance`(不然下一步被冲);② `echo 0 > /proc/irq/130/smp_affinity_list`(core 0 要在网卡所在 NUMA 节点上);③ 固化到 systemd unit / tuned,扛住重启和驱动 reload;④ 验:计数只在 core 0、core 3 `%soft`→0、`ksoftirqd/3` 不再醒。
> - **回炉**:find→bind→verify 的命令序列 + "先杀 irqbalance 再 echo"这个顺序。
>
> 参考骨架:排查——`cat /proc/interrupts` 确认 130 的计数在 core 3 涨;`grep NET_RX /proc/softirqs` 看是不是网络软中断;确认不是 managed IRQ(试写不报 `-EIO`)。处理——先 `systemctl stop/disable irqbalance`,再 `echo 0 > /proc/irq/130/smp_affinity_list`,静态化到 systemd unit。为什么一个动作两个都掉:软中断默认在**吃硬中断的同一个核**上跑,`ksoftirqd/3` 只是这个软中断在 core 3 溢出时的承接线程;把硬中断 130 从 core 3 引走,core 3 不再产生对应的 NET_RX 软中断,`ksoftirqd/3` 也就没活干了。

**Q3. `echo 0` 绑到 core 0、当场确认成功;10 分钟后 core 3 计数又涨。两个独立原因分别是什么?怎么确认是哪个?永久修法?**

> 你的答(2026-09-09):原因一 —— irqbalance,~10 秒一轮把手动绑定冲掉,修法 stop + disable + 静态脚本。原因二 —— "不知道是 1 还是 3"(没答上)。
>
> 评:原因一对,但**是照抄正文** —— 面试里"背出来"和"能现场推"是两回事,而且漏了**怎么确认是它**:`systemctl is-active irqbalance` 在跑 + `smp_affinity_list` 读回已经不是 `0` + 你再 `echo 0` 能撑约 10s 又翻。原因二是 **managed IRQ**(坑一):
> - `echo 0 > /proc/irq/130/smp_affinity` 当场返回 **`-EIO`**(你可能没注意到写失败);
> - 就算看着像成功,内核 managed-affinity 逻辑握着真正的掩码,任何队列重配(`ethtool -L`、链路抖动、驱动 reload)后按自己策略把队列重新摊回所有核,含 core 3;
> - `/proc/interrupts` 里名字常是成对队列名(`mlx5_comp3@...` / `nvme0q3`)。
>
> **两个怎么分**:
>
> | | irqbalance | managed IRQ |
> |---|---|---|
> | `systemctl is-active irqbalance` | active | 不相关 |
> | `echo 0 > .../smp_affinity` | 成功,~10s 后被改回 | **当场 `-EIO`** |
> | `smp_affinity_list` 读回 | 变成别的核 | 一直是内核选的那组,写什么都不变 |
>
> **回炉**:managed IRQ 这个盲点 —— `-EIO` 这个 tell、`isolcpus=managed_irq`。
>
> 参考骨架:原因一——**irqbalance** 在跑,~10 秒一轮把亲和性改回去;确认:`systemctl status irqbalance` 在跑 + `cat /proc/irq/130/smp_affinity_list` 已经不是 `0`;永久修法:stop + disable,静态脚本设死。原因二——**这是 managed IRQ**,你的写入当时可能没真正生效(或被内核忽略),内核按自己的策略把队列摊回包括 core 3;确认:`echo 0 > .../smp_affinity` 返回 `-EIO`,或 `/proc/irq/130/` 下能看到 managed 标记;永久修法:`isolcpus=managed_irq,3` 让内核派队列时避开 core 3,或减少网卡队列数,或上内核旁路。

## 附二:面试快问快答

> 压缩备查,不是学习材料。理解靠正文。

| 问 | 答法骨架 |
|---|---|
| 为什么中断要单独治,绑核 + FIFO 不够? | 硬中断在调度器之上,是 CPU 硬件机制,优先级对它无效;只能路由不能抢占 |
| 上半部 / 下半部? | 上半部关中断、极短、只应答设备 + 登记活;下半部(softirq)做重活,默认在同核跑,溢出给 `ksoftirqd/N` |
| 绑 IRQ 亲和性,影响硬中断还是软中断? | 都影响——软中断跟着硬中断走,所以一次绑定同时管住两者 + 饿死该核 `ksoftirqd` |
| `smp_affinity` vs `smp_affinity_list`? | 位掩码 vs CPU 列表;用列表,掩码易算错 |
| `isolcpus` 能把中断挡在隔离核外吗? | **不能**。它只动调度器。要 `irqaffinity=` 默认掩码 + 逐 IRQ `smp_affinity` + `isolcpus=managed_irq` + 杀 irqbalance |
| irqbalance? | 用户态守护进程,~10s 一轮重分配 IRQ 亲和性,会冲掉手动设置;手动控制就 stop + disable |
| managed IRQ? | 现代驱动内核托管亲和性,写 `smp_affinity` 返回 `-EIO`;靠 `isolcpus=managed_irq` / 减队列数 / 内核旁路 |
| 中断绑哪个核? | 网卡所在 NUMA 节点的管家核;多队列把行情那一队列单独钉一个核 |
| `/proc/interrupts` 里绑不走的行? | `LOC`(时钟,`nohz_full` 压)、`RES`/`CAL`/`TLB`(IPI),每核私有 |
