## 这一章在干嘛

不是新技术,是一份"体检报告"——把 §1(绑核/NUMA)、§2(实时优先级)、§3(中断绑定)已经学过的东西,加上几个还没讲到的边角(RDTSC 计时校准、SMI、透明大页),打包成一份"给你一台裸机,怎么调成能跑实盘资金的低延迟盒子"的实操清单。面试被问到这类系统设计问题,答案骨架基本就是这张表。

源笔记按"什么时候配置"分四段:启动参数 / 中断隔离 / 电源管理 / 其他。我这里**〔补〕**按"在挡什么抖动源"重新归了四类,两种分法可以对照着看:

### 一类:干掉"这个核不该有的中断/时钟"(§2/§3 的延伸)

`isolcpus=managed_irq,7`、`nohz_full=7`、`rcu_nocbs=7`、`nowatchdog`、`hpet=disable` —— 这几条挡的都是 §3 讲过的"非法中断"概念的变种,只是这次的源头不是普通设备中断:

- **调度器的周期性 tick**:`nohz_full` 关掉。前提是这个核上真的只剩一个 busy-poll 的线程——一旦核上又混进第二个线程,tick 会自动恢复,隔离形同虚设。
- **RCU 的自我记账**:内核用 RCU(Read-Copy-Update)做无锁数据结构的延迟回收,回调本身是要占 CPU 的——`rcu_nocbs` 把这部分记账工作挪到非隔离核上。
- **NMI watchdog / HPET**:两个容易被忽略的"隐形定时器",顺手关掉减少全局中断负载。

这正是 §3"上/下半部 + ksoftirqd 归属"那套的延伸——这里多了 RCU 和 watchdog 这两个连 `irqbalance` 都管不到的抖动源(它们根本不是"设备中断",绑核那套工具管不到)。

### 二类:干掉"频率/电源状态波动"(§1 锁频的完整版)

关 Turbo/C-States/P-States、`idle=poll`、`cpupower frequency-set -g performance`、锁 uncore 频率。§1 教过"关超线程、锁频率"的粗线条版本,这里是完整版。

核心直觉:CPU 不是一直满血状态——会根据负载动态调频(P-state)、深度睡眠省电(C-state)、偶尔超频冲一下(Turbo)。这些机制对笔记本续航是好事,对你是灾难,因为**"从睡眠状态被唤醒到跑满频"本身要花时间,而且这个时间不固定**——今天 10µs、明天 15µs,你的延迟就跟着抖。`idle=poll` 更激进:核心永远不睡,原地空转等活干,费电但零唤醒延迟。uncore(LLC + 内存控制器)频率也会独立于核心频率浮动,不锁的话同一段代码今天访存快、明天慢。

### 三类:干掉"内存/IO 局部性"+ 一个软件管不到的硬件中断(§1 NUMA 的延伸 + 一个新东西)

- **THP(透明大页)关闭**:原因很具体——THP 有个后台线程 `khugepaged`,会不定期扫描、合并小页成大页,这个合并动作本身耗时且时机不可预测,对 HFT 就是一次不请自来的延迟尖峰。**这跟 §6 要讲的"大页内存"是两回事**:§6 是你主动申请大页换少缺页,这里是关掉"内核偷偷帮你拼大页"的后台任务,因小失大。
- **`numactl` 绑定**:就是 §1 的 NUMA 局部性,从"绑 CPU"扩展到"绑内存 + 绑 IO 设备"到同一节点。
- **SMI(System Management Interrupt)**:这一节唯一真正意义上的新概念。主板固件(不是操作系统)在硬件层发出的最高优先级中断,连 `isolcpus` 都拦不住——因为它压根不经过 Linux 调度器,CPU 直接切换到固件的 SMM 模式执行。这是你用软件隔离能达到的天花板,再往下只能靠 BIOS/BMC 调优(比如关掉 Legacy USB Support、PCI Lock 这类容易触发 SMI 的选项)。

### 四类:计时本身要准(预告 §32)

`asm volatile("cpuid" ::: ...)` 后面跟 `rdtsc`,或者直接用 `rdtscp`。这是个具体的坑:CPU 乱序执行下,`RDTSC` 这条指令本身可能被提前或推后执行,导致你测的"这段代码耗时"混进了别的指令。`CPUID` 是一条天然的**串行化指令(serializing instruction)**——执行前会把流水线清空、等前面所有指令真正完成,插在 `RDTSC` 前面就能保证 `RDTSC` 不会被乱序提到前面去。`RDTSCP` 更省事,自带"前面的指令不会跑到我后面"的保证,但不管后面,所以有些写法后面还要再插一次 `CPUID` 或 `LFENCE`。

这里只是预告——§32(延迟测量)会把这个和 cycles→纳秒换算、TSC 是否 invariant 一起展开成完整方法论。

## 代码:`process_helper` —— 纯粹是把 §1+§2+§3 封装成一个类

不需要逐行读,扫一遍映射关系就够,里面没有新概念:

| 函数 | 对应哪一章 | 做的事 |
|---|---|---|
| `set_priority` / `set_thread_priority` | §2 | `SCHED_FIFO` 实时调度,分了 4 档优先级(`LowPriority`=1、`NormalPriority`=max/3、`HighPriority`=max/2、`RealtimePriority`=max),不用每次手算数字 |
| `thread_bind_core` | §1 | `pthread_setaffinity_np` 绑核,包一层边界检查(`cpu >= ncpus` 就拒绝) |
| `get_irqs_by_device` / `bind_device_irqs_to_cpu` | §3 | 读 `/proc/interrupts` 找中断号、写 `smp_affinity` 绑核那套,做成了自动化:给个设备名(比如 `"eth0"`),自动找出它可能挂着的所有 IRQ 号,批量绑到指定核 |

唯一值得停一秒的地方:`get_irqs_by_device` 解析 `/proc/interrupts` 时,不能简单按设备名做整字符串匹配——多队列网卡在这个文件里经常写成 `eth0-TxRx-0` 或者 `[eth0]` 这种变体(一个设备好几个队列、好几个 IRQ 号),所以 `contains_device` 要同时处理"前缀匹配"和"方括号包住"两种格式。这是"多队列网卡一个设备对应多个中断号"这个事实在代码里的直接体现——§3 提过多队列 NUMA 感知,这里是它在工具代码里的样子。
