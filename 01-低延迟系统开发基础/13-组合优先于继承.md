核心句：**“组合优先于继承”说的是复用一个具体类的实现时，把它放成成员，不要 public 继承它；Mixin 看起来用了继承，其实是在编译期把几层功能拼成一个类型，是装饰器模式的静态多态版本。**

## 1. 组合与继承：复用实现，把它放成成员

源 :8–31 的订单簿有两种写法（节选）：

```cpp
class InheritanceOrderBook : public std::vector<Order> {   // 继承：直接“是”一个 vector
};

class CompositionOrderBook {                                // 组合：“有”一个 vector
    std::vector<Order> orders_;
public:
    auto size() const noexcept { return orders_.size(); }  // 只暴露需要的接口
};
```

两种写法的性能一样：成员访问和 `size()` 编译后都是直接读 `orders_` 里的字段，`size()` 会被内联。差别全在设计上，继承 `std::vector` 有三个问题：

- **接口全部暴露**：`push_back`、`erase`、`operator[]` 谁都能调。订单簿要守住“按价格排序”“同价按时间排”这类不变量，外面的人随手 `push_back` 一个就破坏了。组合只给出你愿意给的几个函数，不变量由类自己守。
- **析构函数不是虚的**：`std::vector` 的析构函数不是 `virtual`。`std::vector<Order>* p = new InheritanceOrderBook;` 再 `delete p` 是未定义行为（UB）。标准容器本来就不是设计来当基类的。
- **和实现细节绑死**：以后想把底层换成 `std::deque` 或自己的环形缓冲，继承的写法所有调用方都得跟着改；组合的写法只改类内部。

所以规则是：**要的是“用它的实现”，就放成成员（has-a）；只有真的要“当成它来用”（is-a，并且基类就是为被继承设计的，带虚析构函数），才 public 继承。**

（源 :37 用 `%lu` 打印 `size()`，已改正为 `%zu`：`size_t` 在 Windows 64 位上是 `unsigned long long`，`unsigned long` 只有 32 位，`%lu` 会读错。）

## 2. Mixin：用继承语法，在编译期把功能叠成一个类型

**要解决的问题**：一个迭代器要叠几层功能，比如“遍历矩阵”→“只保留奇数”→“值翻倍”，而且想随意组合。

**运行期的做法是装饰器**：每层是一个对象，持有一个指向下一层的 `Iterator*`，接口是虚函数。每加一层，就多一次堆分配、多一次虚调用（间接调用，编译器没法内联），多一次指针检查。这和 #12 轮 3 第 6 节的“运行时虚函数树”是同一种结构。

**Mixin 的做法**（源 :109–136，节选）：每层是一个模板，把下一层当模板参数，继承它。

```cpp
template <class Base>
class OddOnly : public Base {          // 这一层：只保留奇数
public:
    void next() {
        do {
            Base::next();
        } while (Base::valid() && (Base::cell().value % 2 == 0));
    }
};

template <class Base>
class DoubleValue : public Base {      // 这一层：值翻倍
public:
    Cell cell() const {
        Cell x = Base::cell();
        x.value *= 2;
        return x;
    }
};

using Iter = DoubleValue<OddOnly<MatrixWalk>>;   // 模板实参的顺序就是功能叠加的顺序
```

（构造函数是转发参数给 `Base` 的模板构造函数，从略。）`DoubleValue<OddOnly<MatrixWalk>>` 实例化出来是**一个对象**：没有每层一个堆对象，没有 `Iterator*`，没有虚函数。`Base::next()`、`Base::cell()` 都是编译期就确定的直接调用，全部可以内联，编译器还能跨层做常量传播。

这就是 #12 轮 3 讲的**静态多态**：运行期装饰器是动态多态，Mixin 是它的静态版本，和“编译期决策树替代运行时虚函数树”、速查页里“CRTP 替代虚函数”是同一笔交易。源 :48–49 引了一篇外部文章的测量：1000×10000 的矩阵、四层功能，运行期装饰器是基础实现的 2.8 倍，Mixin 只比基础实现多约 15%（外部数据，没有复现）。

## 3. 顺序就是语义

模板实参的顺序决定每层看到的是什么。同一个矩阵 `{{1, 2, 3}, {}, {4, 5, 6}}`，两种顺序实测：

| 类型 | 输出 | 为什么 |
|---|---|---|
| `DoubleValue<OddOnly<MatrixWalk>>` | `2 6 10` | 先在原值上筛奇数（1、3、5），再翻倍 |
| `OddOnly<DoubleValue<MatrixWalk>>` | 空 | 先翻倍，所有值都变成偶数，再筛奇数就一个不剩 |

运行期装饰器可以在运行时按配置决定怎么叠；Mixin 的顺序写在类型里，编译完就定了，换顺序就是换类型。

## 4. 代价

- **类型组合爆炸**：每种组合是一个新类型，都要实例化一份代码，编译时间和二进制体积跟着涨。
- **报错难读**：模板嵌套几层后，编译错误信息很长。
- **构造函数要转发**：每层都要把参数转给 `Base`。源的写法是可变参数模板构造函数；C++11 起也可以用继承构造函数 `using Base::Base;`。
- **名字遮蔽不是重写**：`OddOnly::next()` 只是遮住了 `Base::next()`，不是虚函数重写。拿着 `MatrixWalk&` 去调 `next()`，调到的还是 `MatrixWalk::next()`。Mixin 只在“一直用完整类型”时成立。
