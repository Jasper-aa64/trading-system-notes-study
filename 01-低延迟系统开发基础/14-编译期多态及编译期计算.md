核心句：**这一节讲两件事，都是把运行时的工作挪到编译期。编译期多态把“调哪个实现”定在编译期，运行时没有间接跳转、还能内联；编译期计算把“这个值是多少”定在编译期，运行时直接用算好的常量或表。代价都一样：编译期必须知道答案。**

## 1. 编译期多态：五种写法，同一个思路

上一条（[#13](13-组合优先于继承.md)）和速查页第 3 条讲了静态多态和动态多态的区别：差在“调哪个函数”什么时候定。源列的五种写法都是静态多态，区别只在**编译器靠什么来选实现**：

| 写法 | 编译器靠什么选 | 讲过的地方 |
|---|---|---|
| 函数重载 | 实参的类型 | 本节 1.1 |
| 模板特化 | 模板实参（类型或常量） | 本节 1.2 |
| CRTP | 基类模板参数里写的子类 | 速查页 [1.5](https://jasper-aa64.github.io/zh/ref/cpp-syntax/#virtual-alternatives) |
| `if constexpr` | 编译期条件，没选中的分支不实例化 | #12 轮 3 第 4.1 节 |
| concepts / `requires` | 类型满不满足约束 | #12 轮 3 第 4.3 节 |

### 1.1 函数重载：最简单的编译期多态

同名函数，参数类型不同，编译器在调用处按实参类型选一个，选完就是一次普通的直接调用：

```cpp
const char* describe(int) { return "int"; }
const char* describe(double) { return "double"; }

describe(1);     // 调 describe(int)
describe(1.0);   // 调 describe(double)
```

运行时没有任何“选”的动作，这是它和虚函数的根本区别：虚函数按对象的**实际类型**在运行时选，重载按表达式的**静态类型**在编译时选。

### 1.2 模板特化：给某个模板实参单独写一份

**模板特化（template specialization）**：先声明一个通用模板（主模板），再为某个具体的模板实参单独给出一份实现。用到 `OrderProcessor<OrderType::BUY>` 时，编译器就用为 `BUY` 写的那份。源 :107–124（补全了 `Order`、`OrderType` 和函数体）：

```cpp
enum class OrderType { BUY, SELL };

template <OrderType Type>
struct OrderProcessor;                 // 主模板只声明、不定义

template <>
struct OrderProcessor<OrderType::BUY> {
    static void process(const Order& order) { /* 买单逻辑 */ }
};

template <>
struct OrderProcessor<OrderType::SELL> {
    static void process(const Order& order) { /* 卖单逻辑 */ }
};

template <OrderType Type>
void processOrder(const Order& order) {
    OrderProcessor<Type>::process(order);   // 编译期按 Type 选特化
}
```

几个要点：

- **主模板只声明不定义**是常见写法：哪个枚举值忘了写特化，用到时直接编译报错（不完整类型），而不是运行时走进默认分支。
- **前提是 `Type` 在编译期就知道**，写成 `processOrder<OrderType::BUY>(o)`。如果买卖方向是从行情或订单里读出来的运行时值，还是得先 `if` / `switch` 一次，再进对应的特化。这就是速查页第 3 条讲的“在外层分派一次”。
- 和 `if constexpr` 比：特化把每种情况放在不同的类里，适合每种情况代码多、或者别的模块要能自己加一种特化；`if constexpr` 把几种情况写在同一个函数里，适合每种只有几行。

### 1.3 `if constexpr` 里的 `static_assert(false)`

源 :130–135 用 `else { static_assert(false); }` 兜底：传进来的既不是 `Bear` 也不是 `Duck` 就编译报错。这种写法在 GCC 13、Clang 18 上能过（实测，`-std=c++20` 也能过）：C++ 标准后来把“没走到的分支里的 `static_assert(false)` 不报错”当成缺陷修正，追溯到了旧标准。更早的编译器会不管有没有走到都直接报错。要兼容旧编译器，写成依赖模板参数的条件：

```cpp
template <typename> inline constexpr bool always_false = false;

template <typename Animal>
const char* speak(const Animal& a) {
    if constexpr (std::is_same_v<Animal, Bear>) return a.roar();
    else if constexpr (std::is_same_v<Animal, Duck>) return a.quack();
    else static_assert(always_false<Animal>, "unsupported animal");
}
```

`always_false<Animal>` 的值要等 `Animal` 确定了才知道，所以只有真的实例化到这个分支时才会触发。

### 1.4 concepts 在这里的角色

源 :59–101 的 `GraphBuilder` 例子里，真正“多态”的是 `process_graph` 这个函数模板：传 `BuilderA` 和 `BuilderB` 各实例化一份。concept 本身不负责选实现，它负责**把“这个类型能不能用”写成一个有名字的条件**：不满足的类型在调用处就报错，报错信息是“约束不满足”，而不是模板里面几十行的展开错误。（源这段代码不完整，`HasBuildGraph`、`Graph` 都没定义，`(...)` 也不是合法代码，只能当示意读。）

## 2. 编译期计算：`const` / `constexpr` / `consteval` / `constinit`

四个关键字长得像，回答的是不同的问题。先给一张对比表，再逐个讲：

| 关键字 | 修饰什么 | 保证在编译期算出来吗 | 之后能改吗 |
|---|---|---|---|
| `const` | 变量、参数、成员函数 | **不保证** | 不能 |
| `constexpr` | 变量 | 保证 | 不能 |
| `constexpr` | 函数 | 不保证：用在要求常量的地方才在编译期算 | — |
| `consteval` | 函数 | 保证：每次调用都在编译期算 | — |
| `constinit` | 静态生命周期的变量 | 保证初始化在编译期完成 | **能**（不带 `const`） |

### 2.1 `const`：只读，不是“编译期常量”

`const` 只说一件事：**初始化之后不能再改**。初始值可以是运行时才知道的，比如 `const int scale = get_config("scale");`。

对性能要分清两种情况：

- **`const` 对象本身**：比如 `const int max_len = 100;`。改它是未定义行为，编译器可以认定它不变，直接把 100 当立即数用。整型的 `const` 变量用常量初始化时，还能当编译期常量用（下面 2.5 的 `Vector<vec_dim>`）。
- **`const T*` / `const T&`**：只是说**你**不能通过这个指针改它，不代表别人不会改。编译器照样要防着别的指针写过它。实测：

```cpp
int f(const int* p, int* q) {
    int a = *p;
    *q = 1;          // q 可能和 p 指向同一个 int
    return a + *p;   // 所以这里要重新读 *p
}
```

GCC `-O2` 编出来是 `movl (%rdi), %eax` → `movl $1, (%rsi)` → `addl (%rdi), %eax`，`*p` 读了两次。所以“参数加 `const` 能让编译器优化”基本不成立，`const &` 参数的好处是不拷贝、防误改。想让编译器认定两个指针不重叠，靠的是 `__restrict`（#16 指针访存优化会讲）。

源里 `const` 和 `#define` 的对比表（:164–169）是对的：`const` 有类型、守作用域，宏只是文本替换。

### 2.2 `constexpr`：变量一定编译期算，函数“能”编译期算

源 :224 说 `constexpr` 是“优化提示”、“若可编译期计算则必须在编译期完成”，这不对，已改正。`constexpr` 修饰变量和修饰函数，意思不一样：

- **`constexpr` 变量**：初始值**必须**在编译期算出来，算不出来就编译报错。`constexpr int scale = get_config("scale");` 报错，因为 `get_config` 要运行时才能调。
- **`constexpr` 函数**：意思是“**允许**在编译期算”。用在要求常量的地方（`constexpr` 变量的初始值、模板实参、数组大小、`static_assert`），编译器必须在编译期算；用在普通表达式里、参数是运行时的值，就是一次普通的运行时调用。

```cpp
constexpr int twice(int x) { return x + x; }
constexpr int four = twice(2);          // 编译期算出 4
int twice_rt(int n) { return twice(n); } // n 运行时才知道：运行时算
```

`twice_rt` 编出来就是一条 `leal (%rdi,%rdi), %eax`，和普通函数一样。参数是常量但不在要求常量的地方（比如 `int x = twice(2);`），标准不要求编译期算，只是优化器一般会顺手算掉。

源 :235–238 列的限制（不能有 `static` 局部变量、不能调非 `constexpr` 函数）是旧标准的说法。C++23 起这些可以**写**在 `constexpr` 函数里，只是编译期求值时不能**走到**它们。源自己在 :395 也是这么说的。

### 2.3 `consteval`：每次调用都必须在编译期

`consteval` 函数叫**立即函数（immediate function）**：每次调用都必须在编译期算完，参数不是常量就编译报错。用在“这个值必须编译期就有，运行时算就是 bug”的地方，比如编译期校验一个配置、生成一个哈希值。

```cpp
consteval int get_dim() { return 4; }
Vector<get_dim()> v;     // 可以当模板实参
```

源 :421 的陷阱说得对：`consteval` 函数的**形参在函数体里不是常量表达式**。虽然每次调用都在编译期，但函数体是按“一个普通参数”来写的，不能 `static_assert(i == 1)`，也不能拿 `i` 当模板实参。要用就得让它变成模板参数（`template <int I>`）。

### 2.4 `constinit`：静态变量在编译期初始化，但可以改

源 :244–251 有两处不对，已改正：`constinit` **不**隐含 `const`，初始化之后可以改；它和 `consteval` 也没有关系。`constinit` 只管一件事：**静态生命周期的变量（全局变量、`static` 变量）的初始化必须在编译期完成**。

```cpp
constexpr int somefunc() { return 27; }    // 必须是 constexpr
constinit int g_counter = somefunc();      // 编译期初始化成 27
// ...
++g_counter;                               // 可以改，变成 28
```

GCC 把 `g_counter` 放在 `.data` 段，初值 27 直接写在可执行文件里，程序一启动就是 27，没有运行时初始化的代码。

它解决的问题：全局变量如果是运行时初始化的（初始值来自普通函数调用），由启动代码在 `main` 之前去算。不同源文件里的全局变量谁先初始化，标准不规定，一个全局变量的初始化读了另一个还没初始化的，就是 bug（static initialization order fiasco，静态初始化顺序问题）。`constinit` 让这件事在编译期就有保证，做不到就编译报错。

源 :258–269 的例子里 `somefunc()` 是普通函数，`constinit` 那行会编译失败；`#ifdef` 是预处理阶段选的分支，和 `constinit` 无关。正确写法是把 `somefunc` 写成 `constexpr`，如上。

### 2.5 非类型模板参数：把一个常量变成类型的一部分

**非类型模板参数（NTTP，non-type template parameter）**：模板参数不是类型，而是一个值。源 :281–299（去掉了 `template <const int Dim>` 里多余的 `const`，模板参数本来就是常量）：

```cpp
template <int Dim>
struct Vector {
    float data[Dim];
    float dot(const Vector& other) const {
        float sum = 0.0f;
        for (int i = 0; i < Dim; i++) sum += data[i] * other.data[i];
        return sum;
    }
};

const int vec_dim = 4;
Vector<vec_dim> v1, v2;     // Vector<4>：循环次数是编译期常量
```

`Dim` 是类型的一部分：`Vector<4>` 和 `Vector<8>` 是两个不同的类型，各编一份代码，循环次数是常量，编译器可以整个展开或向量化，不用在运行时判断维度。代价就是速查页第 3 条讲的代码膨胀：每个维度一份。

能当模板实参的必须是编译期常量。`const int vec_dim = 4;` 可以（整型 `const`、用常量初始化），`int n = 4; const int runtime_dim = n;` 不行，因为 `n` 不是常量（源 :376–378 说得对）。

### 2.6 `if consteval`（C++23）：同一个函数，编译期和运行时走两套实现

```cpp
constexpr std::size_t my_strlen(const char* s) {
    if consteval {
        std::size_t n = 0;          // 编译期：一个字节一个字节数
        while (s[n]) ++n;
        return n;
    } else {
        return std::strlen(s);      // 运行时：用库里优化过的版本（std::strlen 不是 constexpr）
    }
}
static_assert(my_strlen("hello") == 5);
```

用途是：编译期只能用 `constexpr` 能跑的写法，运行时想用更快的实现（库函数、SIMD、内联汇编），两边共用一个函数名。

### 2.7 怎么选

- 值必须编译期就有，算不出来应该报错 → `constexpr` 变量，或者 `consteval` 函数。
- 一份实现编译期、运行时都要用 → `constexpr` 函数，需要的话加 `if consteval`。
- 全局 / `static` 变量，要可改，但不想要运行时初始化 → `constinit`。
- 只是不想被改 → `const`。

## 3. 查找表（LUT）与预计算：用空间换时间

**查找表（LUT，lookup table）**：提前把结果算好放进数组，运行时按下标取。#12 轮 2 的 `fee_lookup`、编译器把 `switch` 换成的 `CSWTCH` 值表都是这个。

源 :438–445 把“什么时候算”分成四个时机：

| 时机 | 怎么做 | 适合 |
|---|---|---|
| 编译前（离线） | 另写程序生成数据文件或 C++ 源码 | 很大、很少变的表 |
| 编译时 | `constexpr` 函数填数组 | 能用常量算出来的小表 |
| 程序启动时 | 初始化函数填表 | 依赖配置的表 |
| 第一次用到时 | 延迟计算 | 很少用到的表（要注意线程安全，第一次调用慢） |

编译时生成的例子：

```cpp
constexpr std::array<uint64_t, 20> make_pow10() {
    std::array<uint64_t, 20> t{};
    uint64_t v = 1;
    for (auto& x : t) { x = v; v *= 10; }
    return t;
}
constexpr auto kPow10 = make_pow10();     // 编译期填好，放进 .rodata
uint64_t pow10(unsigned e) { return kPow10[e]; }
```

`kPow10` 在 `.rodata`（只读数据段），20 个值直接写在可执行文件里；`pow10` 编出来是 `leaq kPow10(%rip), %rax` + `movq (%rax,%rdi,8), %rax`，一次读内存。

要记的代价：**查表是一次读内存，表大了会缓存未命中**。表在 L1D 里，一次读约 1 ns；表大到几十 KiB 以上、访问又随机，就会落到 L2、L3 甚至内存（[11补](11-补-内存层级-延迟与带宽.md)），这时候直接算可能比查表快。几次乘法加法能算出来的东西，不一定值得做成表。

## 4. 还没法验证的两个 C++26 特性

- **`std::nontype_t`**（源 :305–355）：把一个常量通过参数类型带进普通函数，让它在函数体里当模板参数用，主要给 `std::function_ref` 用。GCC 13 没有实现，这里不展开。（我印象里后来的 C++26 草案把它换成了更通用的 `std::constant_wrapper`，没有核实。）
- **`template for`**（源 :448–462）：编译期循环，编译器把循环体按次数复制展开，每次的循环变量是常量。源写的 `0..4` 不是 C++ 语法，实际要写成遍历一个编译期的序列（比如 `std::array` 或参数包）。GCC 13 不支持，没有验证。
