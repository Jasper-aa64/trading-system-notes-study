核心句：**源笔记列了十几种循环变换，大部分 GCC 在 `-O2` / `-O3` 下自己会做。值得你操心的是两类事：一是有什么挡住了编译器（浮点求和的顺序、指针可能重叠、调用没内联），二是编译器不会替你做的（改数据的走法、分块、改算法）。**

## 1. 循环慢在哪：三类原因

一个循环慢，通常是下面三件事之一，每种变换都是冲着其中一件去的：

- **每轮做了多余的事**：不变的值每轮重算、循环里判断一个不变的条件。对应外提、强度削弱、unswitching（第 2 节）。
- **迭代之间有依赖，没法并行**：这一轮要等上一轮的结果。对应多个累加器、软件流水（第 3 节）。
- **访存走法差**：跳着读、同一批数据被反复从内存搬进来。对应交换、分块、融合（第 4 节）。

“循环判断 `i < n` 和 `i++` 的开销”在现代 CPU 上很小：`cmp` + `jne` 会合成一条微操作，这个分支几乎每次都猜对。所以展开本身省下的不多，它的价值在于给后面的变换腾地方（2.4 节）。

## 2. 编译器自己会做的变换

### 2.1 循环不变量外提（LICM）：只算一次的东西搬到循环外

循环里每轮结果都一样的计算（数组长度、常量系数、成员变量），编译器会提到循环前只算一次。#14 轮 1 §2〔补〕的 `sum_crtp` 就是例子：`mult` 被提到循环外只读一次。

挡住它的两种情况：

- **调用没内联**：编译器看不见函数体，就不敢假设被调函数没改那个值（`sum_virtual` 每轮在被调函数里重读 `mult`）。
- **指针可能重叠**：循环里通过 `int* q` 写，编译器不能确定没写到 `*p`，`*p` 就得每轮重读（[速查 4.1](https://jasper-aa64.github.io/zh/ref/cpp-syntax/#const) 的例子）。#16 会讲 `__restrict`。

### 2.2 强度削弱（strength reduction）：乘法换成累加

把 `a[i] = 10 * i` 里的乘法换成每轮加 10，手写出来是这样（验证程序里的 `fill_10i` / `fill_10i_sr`）：

```cpp
void fill_10i(int* a, int n) {          // 原写法
    for (int i = 0; i < n; i++) a[i] = 10 * i;
}

void fill_10i_sr(int* a, int n) {       // 强度削弱后
    int x = 0;
    for (int i = 0; i < n; i++) {
        a[i] = x;                       // x 始终等于 10 * i
        x += 10;
    }
}
```

这一步编译器自己会做。实测 `-O2` 下两个函数编出来的循环一模一样，都是 `movl %eax, (%rdi)` + `addl $10, %eax`，没有乘法。

源里说累加会引入迭代间依赖、没法并行，说得过强：`x` 是**归纳变量**（每轮按固定步长变化的变量），编译器认得它，知道第 i 轮的值就是 $10i$。`-O3` 下两种写法都向量化了，一次写 4 个：

- `fill_10i_sr`：一个寄存器里放 `{0, 10, 20, 30}`，每轮整体加 40（`paddd`）。
- `fill_10i`：寄存器里放 `{0, 1, 2, 3}`，每轮整体加 4，再用移位和加法算出 ×10：`pslld $2`（×4）、`paddd`（加上自己，得 ×5）、`pslld $1`（×2）。

所以这一条不用手写，直接写 `10 * i` 就行。

### 2.3 循环旋转（loop rotation）：`for` 变成 `do-while` 加一个前置判断

```text
for (i = 0; i < n; i++) body;     →     if (0 < n) { i = 0; do { body; i++; } while (i < n); }
```

前面那个 `if` 叫 **loop guard**。旋转之后，进到 `do` 里就保证循环体至少执行一次。这样把循环体里的不变计算提到 `do` 前面才安全：如果 `n` 是 0，原来的循环一次都不执行，提出来的计算也不能执行（比如它会读一个可能无效的指针）。所以它是给外提打基础的，你在汇编里看到的循环，几乎都是这个形状：先 `testl %edx, %edx; jle` 跳过，循环判断放在末尾。

### 2.4 循环展开（unrolling）：少判断几次，但不缩短依赖链

把循环体复制几份，每轮处理几个元素，`i < n` 和 `i++` 就少执行几次。源 :56 的 4 级展开：

```cpp
for (; i < n - 3; i += 4) {
    sum += v1[i] * v2[i];
    sum += v1[i+1] * v2[i+1];
    sum += v1[i+2] * v2[i+2];
    sum += v1[i+3] * v2[i+3];
}
for (; i < n; i++) sum += v1[i] * v2[i];   // 剩下的 0–3 个
```

这段展开了，但**只有一个 `sum`**：四个加法还是一个等一个（3.2 节）。实测 `-O3` 下它和不展开的版本编出来几乎一样：4 个乘法合成一条 `mulps`，4 个加法仍是 4 条串行的 `addss`。展开真正有用，是和多个累加器、向量化一起用；而 `-O3` 下编译器会自己展开，手写展开一般不必要。

源 :74 / :164 说“展开因子与 SIMD 宽度匹配”，并给了宽度：SSE 一次 4 个 `float`，AVX / AVX2 一次 8 个，AVX-512 一次 16 个。源里“GPU warp 为 32 位”应为 **32 个线程**。

### 2.5 循环外提判断（loop unswitching）：源里叫“循环分布”

循环里判断一个整个循环都不变的条件：

```cpp
for (int i = 0; i < n; i++) {
    if (do_add) a[i] += b[i];
    else        a[i] -= b[i];
}
```

把判断提到循环外、拆成两个各自干净的循环，叫 **loop unswitching**。源 :25 把它叫“循环分布（loop distribution）”，那个名字在文献里指的是第 4.3 节的循环分裂，已按正确名字写。手写出来就是：

```cpp
void add_or_sub_unswitched(float* a, const float* b, int n, bool do_add) {
    if (do_add) {
        for (int i = 0; i < n; i++) a[i] += b[i];
    } else {
        for (int i = 0; i < n; i++) a[i] -= b[i];
    }
}
```

**`-O2` 不做。** 判断留在循环里，每轮都要 `testb` 一次，一次只算一个：

```text
.L5:
    movss  (%rdi,%rax), %xmm0     # 读 a[i]
    movss  (%rsi,%rax), %xmm1     # 读 b[i]
    testb  %cl, %cl               # 每轮判断一次 do_add
    jne    .L10                   # 真：去 addss 那边
    subss  %xmm1, %xmm0
    movss  %xmm0, (%rdi,%rax)
    ...
```

**`-O3` 替你做了。** `-fopt-info-loop` 报 `unswitching loop 1 on 'if' with condition: do_add`。函数开头只判断一次，然后分成两份循环，各自向量化：

```text
    testb  %cl, %cl               # 只判断这一次
    jne    .L3                    # 真：走加法那份
    ...                           # 假：走减法那份（结构一样，用 subps）
.L16:                             # 加法那份的主循环，一次 4 个
    movups (%rax,%rcx), %xmm0
    movups (%rsi,%rcx), %xmm3
    addps  %xmm3, %xmm0
    movups %xmm0, (%rax,%rcx)
    addq   $16, %rcx
    cmpq   %rdi, %rcx
    jne    .L16
```

每一份进循环之前，还会先比一下 `a` 和 `b` 的地址：两者重叠就走逐个算的版本，不重叠才走向量版。这是[#16 §1.2](16-指针访存优化.md)讲的循环多版本，和 unswitching 是两回事，只是碰巧叠在一起。

这个分支本来也不会猜错（`do_add` 整个循环不变），所以 unswitching 省下的不是猜错的代价，是每轮那次判断，更重要的是换来了向量化：判断留在循环里时，编译器很难把 4 轮并成一条指令。代价是代码多了一份。在 `-O2` 下照上面手写（或者把 `do_add` 做成模板参数，在编译期分成两个函数），能去掉每轮的判断，但实测仍然不向量化，还是逐个 `addss` / `subss`：`-O2` 的向量化很保守（第 6 节）。要两样都拿到，就用 `-O3`。

## 3. 依赖链：循环能不能并行，看迭代之间有没有依赖

### 3.1 迭代间依赖：读后写的真依赖才挡路

两条语句访问同一个位置，按先后有三种关系：

- **RAW（写后读，真依赖）**：先写、后读，后面要用前面写的值。跨迭代的例子：`a[i] = a[i-1] * 2 + b[i]`，第 i 轮要等第 i-1 轮写完 `a[i-1]`。这条链拆不掉，就不能把几轮并起来做。
- **WAR（读后写）**：先读、后写，例如同一轮里 `a[i] = b[i]; b[i] = c[i];`，只要读在写之前就行。
- **WAW（写后写）**：两次写同一个位置，最后留下哪个值要对。

WAR 和 WAW 是“名字冲突”，换个变量名、多用一个临时变量就能消掉；只有跨迭代的 RAW 是真正挡住向量化的。源 :157 把 `a[i] = b[i]; b[i] = c[i]` 标成 RAW、把 `a[i] = b[i-1]` 标成 WAR，正好标反了，已按上面改正。

### 3.2 浮点求和：编译器不敢换顺序，要多个累加器

点积 `sum += v1[i] * v2[i]` 里，每次加法都要等上一次加完，这是一条贯穿整个循环的 RAW 链。整数求和编译器可以随便换顺序，实测 `isum` 在 `-O3` 下直接向量化（`paddq`）；`float` 不行，因为浮点加法不满足结合律，`(a + b) + c` 和 `a + (b + c)` 舍入结果可能不同，编译器默认不能改你的求和顺序。

实测 `-O3` 下基础点积的循环体：

```text
.L4:
    movups  (%rcx,%rax), %xmm1      # 读 4 个 v1
    movups  (%rsi,%rax), %xmm3      # 读 4 个 v2
    addq    $16, %rax
    mulps   %xmm3, %xmm1            # 4 个乘法一次做完
    addss   %xmm1, %xmm0            # 下面 4 个加法一个等一个
    ...shufps / unpckhps 取出第 2、3、4 个积...
    addss   %xmm2, %xmm0
    addss   %xmm2, %xmm0
    addss   %xmm1, %xmm0
    cmpq    %rdi, %rax
    jne     .L4
```

`-fopt-info-vec` 照样报“loop vectorized”，但加法链一点没变短。一次浮点加法延迟约 3–4 个周期，每 4 个元素就是 12–16 个周期（估算）。

改法是**多个累加器**：

```cpp
float s0 = 0, s1 = 0, s2 = 0, s3 = 0;
int i = 0;
for (; i + 3 < n; i += 4) {
    s0 += v1[i] * v2[i];
    s1 += v1[i + 1] * v2[i + 1];
    s2 += v1[i + 2] * v2[i + 2];
    s3 += v1[i + 3] * v2[i + 3];
}
for (; i < n; i++) s0 += v1[i] * v2[i];
return (s0 + s1) + (s2 + s3);
```

四条链互不依赖，编译器把四个累加器装进一个寄存器，循环体变成一条 `mulps` + 一条 `addps`，每 4 个元素只等一次加法，约 3–4 个周期，约快 4 倍（估算）。累加器再多（比如 8 个，两个向量寄存器轮流加），还能把加法单元的几条流水线填满。代价是求和顺序变了，结果可能和逐个加差最后几位；这是你明确接受的，所以要自己写。另一条路是 `-ffast-math`（或只开 `-fassociative-math`）允许编译器换顺序，实测基础版也变成 `addps`，但它是整个编译单元的开关，还会改别的浮点行为（例如 4.3 节的除法），交易系统里一般不全局开。

### 3.3 软件流水与 MII：吞吐上限由资源或依赖环决定

**软件流水**（software pipelining）是让相邻几轮迭代重叠执行：第 i 轮还在算，第 i+1 轮已经开始读数据。**启动间隔**（II，initiation interval）是相邻两轮开始之间隔几个周期，II 越小吞吐越高。它有一个下界 MII，由两件事决定：

$$
\text{MII} = \max(\text{ResMII},\ \text{RecMII})
$$

- **ResMII（资源约束）**：每轮要用几次某类执行单元，除以这类单元有几个，取所有类里最大的：

$$
\text{ResMII} = \max_{\text{每类单元}} \left\lceil \frac{\text{每轮这类指令条数}}{\text{这类单元个数}} \right\rceil
$$

  源 :215 的例子：每轮 3 条加法、2 条乘法，2 个加法单元、1 个乘法单元，加法 $\lceil 3/2 \rceil = 2$，乘法 $\lceil 2/1 \rceil = 2$，ResMII = 2。

- **RecMII（依赖环约束）**：跨迭代的依赖环上，所有指令延迟加起来，除以这个环跨了几轮：

$$
\text{RecMII} = \max_{\text{每个依赖环}} \frac{\text{环上延迟之和}}{\text{环跨越的迭代数}}
$$

  源 :236 的例子 `a[i] = a[i-1] * 2 + b[i]`：环是“乘、加、写回 `a[i]`、下一轮读”，源里假设乘法 2 个周期、加法 1 个周期，RecMII = 3；ResMII 是 2，所以瓶颈在依赖环，执行单元再多也没用。（源里的延迟是假设的数；x86 上 `* 2` 会被编成加法或移位，`a[i-1]` 也会留在寄存器里，不真去读内存。）

在 x86 上这件事主要由硬件做：乱序执行同时挂着好几轮迭代，自动把它们重叠起来，编译器很少显式做软件流水。但这套算法照样有用，它就是 [#5 轮 5](05-内存模型与缓存及流水线.md) 讲的关键路径：**看循环快不快，先找跨迭代的依赖链（RecMII），再数每轮占用的执行单元（ResMII），大的那个就是上限。** 3.2 节的点积就是 RecMII 卡住的例子：一条加法链，每轮至少等一次加法延迟；多个累加器把一个环拆成四个互不相干的环，RecMII 变成原来的 1/4。

## 4. 访存：让数据少搬几次

### 4.1 循环交换（interchange）：内层沿着内存连续的方向走

C++ 二维数组按行存，`m[i][j]` 和 `m[i][j+1]` 挨着。内层循环走 `j`，就是顺着内存读，一条缓存行 64 B 用满、预取器跟得上；内层走 `i`，每步跳一整行，每次都可能是一条新的缓存行。交换内外层就能从后者变成前者，#11 轮 3 和 11补 讲过的“按列遍历慢”就是这个。编译器只在能证明结果不变时才自己交换，通常要你写对。

### 4.2 循环分块（tiling）：有重复使用才有用

分块是把大数组切成小块，一块处理完再处理下一块，让块内的数据在被反复使用期间一直留在缓存里。前提是**数据有重复使用**：矩阵乘法里同一行、同一列要用很多次；转置时按行读、按列写，按块走能让读和写都留在缓存里（验证程序里的 `transpose_tiled`）。

```cpp
constexpr int N = 256, T = 16;
void transpose_tiled(const float* a, float* b) {
    for (int i = 0; i < N; i += T)
        for (int j = 0; j < N; j += T)
            for (int ti = i; ti < i + T; ti++)
                for (int tj = j; tj < j + T; tj++)
                    b[tj * N + ti] = a[ti * N + tj];
}
```

〔补〕**转置里重复使用的是缓存行，不是元素**（2026-10-12，另一个会话质疑块内对 `b` 的跨步写会“严重缓存未命中”）。转置每个元素也只碰一次，但 `b` 的一条缓存行装 16 个 `float`，要分 16 次写满：
- **不分块**：内层走 `j`，写 `b[j*N+i]`，每步换一条新的行。同一条行的第 2 次写，要等写完一整列 N 条别的行之后才轮到。N 大时这 N 条行装不下 L1；这里 N = 256 虽然只有 16 KiB，但行与行相隔 1 KiB，按组号 $(\text{地址} / 64) \bmod 64$ 算只落进 4 个组，8 路的 L1 最多留 32 条，行早被挤掉了，一条行要被搬进来 16 次。
- **分块**：块内 `tj` 循环同样跨步写，但只碰 16 条 `b` 的行（1 KiB）。`ti` 走 16 遍，每遍给这 16 条行各写一个 `float`，16 遍后正好写满、再离开。这 16 条行落在 4 个组里，每组 4 条，8 路装得下。跨步写打在 L1 里的行上，和顺序写一样便宜；每条行只从下一级搬进来 1 次。所以“块内跨步写导致颠簸”不成立，这正是分块解决的问题。

那个会话建议先把 `a` 的块拷进栈上的 `tile[T][T]`，再从 `tile` 按行写 `b`。代码是对的，但不会更快（按访存量分析，没有计时）：
- `a`、`b` 每条行照样各搬 1 次，访存量不变，只是多了一遍 1 KiB 的拷贝。
- 跨步没有消失，只是从写 `b` 挪到了读 `tile[ti][tj]`（`ti` 在内层）。
- 1 KiB 的 `tile` 放不进寄存器（16 个 `xmm` 一共 256 B）。

这种写法来自 GPU：GPU 上跨步写显存不会被缓存合并，每次都是单独一笔事务，所以要先在 shared memory 里倒一手。CPU 上 L1 已经替你做了这件事。CPU 上真正的下一步是**寄存器里的转置**：一次读 4 行各 4 个 `float` 进 4 个 `xmm`，用 `unpcklps` / `shufps` 交换成 4 列（`_MM_TRANSPOSE4_PS`），再整行写回。这样读和写都是 16 B 一条指令，而不是一次一个 `float`。

源 :89 用“清零矩阵”举例，这个例子分块没有用：每个元素只写一次，按行一路写下去本来就是最好的走法。实测 GCC `-O2` 把不分块的版本整个编成一次 `memset`，分块版本反而只能每行写 64 B、再跳 2 KiB 到下一行。

### 4.3 融合与分裂（fusion / fission）：一遍还是几遍

- **融合**：对同一批数据做的几件事放进一个循环，数据只从内存搬一次。代价是循环体变大，寄存器可能不够、可能挡住向量化，也占更多指令缓存。
- **分裂**：反过来，一个循环拆成几个，每个循环体简单、好向量化，但数据要扫几遍。

源 :19 的“函数链式组合”讲的就是这个权衡，结论是对的：数据放得进 L2 / L3 时，多扫几遍还是命中缓存，分开写更好；数据远大于缓存时，每多扫一遍就是多一遍内存带宽，融合更好。

源 :124 的 BatchNorm 例子要改正：`v[i] = (v[i] - mean) / denom` 这个单循环本来就能向量化，实测 `-O3` 编出 `subps` + `divps`，一次 4 个。拆成“先全部减、再全部乘”两遍，没有让哪个循环更好向量化，只是多扫了一遍数组。源里“提升 2~4 倍”是 GPU 的说法，没有依据。这个例子里真正省时间的是**把除法换成乘倒数**：除法延迟约 10–15 个周期、吞吐也慢好几倍，乘法约 3–4 个周期。一遍做完就行：

```cpp
float inv_denom = 1.0f / sqrtf(var + eps);
for (int i = 0; i < n; i++) v[i] = (v[i] - mean) * inv_denom;
```

编译器默认不会替你做这一步，因为乘倒数和直接除的结果可能差最后一位；`-ffast-math` 下它会做（实测 `divps` 变成 `mulps`）。

### 4.4 扁平化（collapsing）：两层循环并成一层

#### 4.4.1 场景：每行只有 3 个数

`rows` 个品种，每个品种存 `cols` 档价格，一行挨一行地放在一块连续内存里。现在要把所有价格乘一个换算系数 `s`。档数是运行时配置的，比如 3 档：

```cpp
void scale_nested(float* m, int rows, int cols, float s) {
    for (int i = 0; i < rows; i++)
        for (int j = 0; j < cols; j++)
            m[i * cols + j] *= s;
}
```

验证程序里是 `scale_nested` / `scale_flat`。`-O3` 会向量化这段代码，但向量化的是**内层**循环：一条 `mulps` 一次乘 4 个 `float`，内层要至少 4 轮才进得去。剩下不够 4 个的，先用 `movq` / `mulps` / `movlps` 处理 2 个，再用 `movss` / `mulss` / `movss` 处理 1 个，这就是**余数处理**。`cols = 3` 时，每一行实际走的是下面这条路（GCC 13 `-O3` 实测汇编，按执行顺序摘出）：

```text
.L3:                               # 新的一行
    cmpl    $2, %r12d              # cols - 1 <= 2？也就是不够 4 个
    jbe     .L24                   # 是：4 个一组的主循环一次都不进
.L8:
    movl    %edi, %r15d            # 算剩几个：3
    subl    %r14d, %r15d
    cmpl    $1, %r15d
    je      .L6
    ...
    movq    (%r14), %xmm1          # 先做 2 个
    mulps   %xmm3, %xmm1
    movlps  %xmm1, (%r14)
    testb   $1, %r15b              # 还剩 1 个吗？
    je      .L5
    ...
.L6:
    movss   (%rax), %xmm1          # 再做 1 个
    mulss   %xmm0, %xmm1
    movss   %xmm1, (%rax)
.L5:                               # 这一行结束，更新行号、行首地址
    addl    $1, %r9d
    addq    %r13, %rsi
    ...
    cmpl    %r9d, %r11d
    jne     .L3
```

一行 3 个数，要走大约 30 条指令、4 个条件跳转，真正干活的只有 2 次乘法（一次乘 2 个、一次乘 1 个）。按 4 个一组跑的 `mulps` 主循环一次都没用上。问题不在于向量化失败，而在于**每一行都要重新进一次内层循环**：算这一行剩几个、走余数分支、更新行号和行首地址。行越短，这些固定开销占比越大。

#### 4.4.2 并成一层：不管行在哪里断开

行和行之间没有空隙，第 `i` 行第 `j` 个就是第 `i * cols + j` 个。乘法对每个数都一样，不用知道它属于哪一行。所以可以把整块内存当成一个长度 `rows * cols` 的一维数组：

```cpp
void scale_flat(float* m, int rows, int cols, float s) {
    int total = rows * cols;
    for (int k = 0; k < total; k++)
        m[k] *= s;
}
```

```text
.L28:
    movups  (%rax), %xmm1          # 一次读 4 个
    addq    $16, %rax
    mulps   %xmm2, %xmm1           # 一次乘 4 个
    movups  %xmm1, -16(%rax)
    cmpq    %rax, %rdx
    jne     .L28
```

4 个数 6 条指令、1 个跳转。一组 4 个数可能横跨两行（第 0 行的 3 个加上第 1 行的第 1 个），这没关系，因为每个数做的事一样。余数处理只在整个数组的末尾做 1 次，而不是每行 1 次。按指令数估算，每个数从约 10 条降到约 1.5 条；没有计时。

#### 4.4.3 什么时候不用手写，什么时候不能并

- **列数是编译期常量时，编译器自己会做。** 把 `cols` 写死成 3，GCC 先把内层 3 轮完全展开，再向量化外层：一轮处理 4 行、12 个数，`movups` 读 48 B，3 条 `mulps`。效果和扁平化一样。`-fopt-info` 报的是 “loop with 3 iterations completely unrolled” 和外层的 “loop vectorized”。要手写的是列数运行时才知道的情况。
- **行和行之间有空隙就不能并。** 比如每行补齐到 64 B（对齐用的填充），或者是 `std::vector<std::vector<float>>`（每行单独分配，在内存里不挨着）。并成一层会碰到填充，或者干脆越界。
- **每个数做的事和行号有关就不能直接并。** 比如每行乘自己的系数 `s[i]`。这时要么先用 `k / cols` 算回行号（多一次除法，得不偿失），要么保持两层。

## 5. 边界：剥离、余数、哨兵

### 5.1 剥离（peeling）与余数循环：把不规整的几轮单独拿出来

向量化的主循环一次处理 4 个（或 8 个），`n` 不是 4 的倍数时，剩下的 0–3 个要单独处理，这段叫**余数循环**（remainder，也叫 epilogue），2.4 节的第二个 `for` 就是。**剥离**是把开头或结尾的几轮单独拿出来，例如先单独做几个元素，让主循环的起始地址对齐到 16 B 或 32 B。两者目的一样：主循环里不再有“这一轮是不是特殊情况”的判断。编译器向量化时会自动生成余数循环（3.2 节汇编里 `.L4` 之后那段逐个 `mulss` 就是）。源 :175 的“剥离前 / 剥离后”两段代码做的不是同一件事（前一段每 4 个里特殊处理 1 个，后一段只特殊处理开头 `n % 4` 个），按上面的说法理解即可。

### 5.2 哨兵（sentinel）：在末尾放一个必然命中的值，循环里少一个判断

在数组里找第一个负数，正常要每步判断两件事：`i < n` 和 `a[i] < 0`。在末尾多留一格放一个负数，循环一定会在它那里停下，就只用判断 `a[i] < 0`：

```cpp
int find_first_negative(int* a, int n) {   // a 至少有 n + 1 格
    int saved = a[n];
    a[n] = -1;
    int i = 0;
    while (a[i] >= 0) ++i;
    a[n] = saved;
    return i;                              // == n 表示没找到
}
```

条件是数组末尾真的多出一格、可写，而且没有别的线程同时在读这个数组。

## 6. 怎么查编译器做了什么

不用猜，让 GCC 自己说：

- `-fopt-info-vec`：哪些循环向量化了、用多宽的向量。
- `-fopt-info-vec-missed`：哪些没向量化、为什么（指针可能重叠、有调用、浮点不能换顺序……）。
- `-fopt-info-loop`：展开、unswitching 这类循环变换。
- 再配合 `-S` 看循环体：3.2 节说明“报告说向量化了”不等于加法链变短了，最后还是要看指令。

GCC 12 起 `-O2` 也开了向量化，但只用最保守的代价模型；实测在 `-O2` 下，普通写法的循环（基础点积、整数求和、`fill_10i`、BatchNorm、`add_or_sub`）都没有向量化；只有手写成每轮 4 条相同语句的两个点积版本，被合成了向量乘法（多累加器版连加法也成了 `addps`）。这叫 SLP 向量化：把一轮里几条一样的语句并成一条向量指令，不是把几轮循环并起来。`-O3` 下这些循环都向量化了。热路径上的关键循环，要么用 `-O3` 编，要么对着报告确认。
