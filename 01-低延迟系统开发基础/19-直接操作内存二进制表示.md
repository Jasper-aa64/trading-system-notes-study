核心句：**把同一块内存当成另一种类型读写，要走编译器认得的路：`memcpy` 或 `std::bit_cast`，编出来一条指令。指针强转和 union 双关违反严格别名，编译器照样按“类型不同就不重叠”优化，会读到旧值。改符号这类有数学写法的，直接写数学式子，编译器自己用位运算。**

## 1. IEEE 754：符号、指数、尾数

源笔记没讲为什么“置最高位”就变成负数，先补这个。double 64 位分三段：最高 1 位是符号，接着 11 位是指数，剩下 52 位是尾数：

$$x = (-1)^{s} \times 1.f \times 2^{\,e - 1023}$$

尾数前面默认有一个 1 不存；指数存的时候加了偏置 1023。100 = 1.5625 × 2⁶：符号 0，指数存 6 + 1023 = 1029（0x405），1.5625 = 1.1001₂，尾数存 1001 后面补 0，拼起来是 0x4059000000000000（实测 `bits_cast(100.0)` 就是这个数）。所以只把第 63 位置 1 就是 −100（0xC059000000000000）。float 是 1 + 8 + 23 位、偏置 127：源 :24 的 2.0f 是 0x40000000，置第 31 位得 0xC0000000，就是 −2.0f。博客里有一张三段位布局的图。

## 2. 改符号不用碰位

直接写数学式子，编译器就编成位运算：`-x` 是一条 `xorpd`（和 0x8000000000000000 异或），`std::fabs(x)` 是一条 `andpd`（和 0x7FFF…FFFF 与），`-std::fabs(x)` 是一条 `orpd`，就是源 :11 想做的“把最高位置 1”，值一直待在浮点寄存器里。手写成 `std::bit_cast` 再 `|`，实测反而是三条（`movq` 进整数寄存器、`btsq`、`movq` 回来）。

真正要把数当成一串位来读写的是两种情况：数据本来就是字节（交易所二进制行情里的价格字段，从收包缓冲区里取 8 个字节读成 double），或者要的就是位本身（算哈希、按整数比大小、序列化）。

## 3. 严格别名：指针强转为什么会读到旧值

**严格别名**（strict aliasing）：一块内存放的是什么类型的对象，就只能通过这个类型（或 `char`、`unsigned char`、`std::byte`）读写。反过来，编译器可以假设两个类型不同的指针不指向同一个对象，这和 [#16](16-指针访存优化.md) 的 `__restrict` 是同一类信息，只是按类型自动推出来。源 :10 的 `(uint64_t *)(&x)` 正好违反它。

源 :6 的 `main` 在 GCC `-O2` 下实测能打印出 `x:-100.00`，因为两个指针都从 `&x` 来，编译器这次看得出来；但 GCC `-Wall` 在 `*x_as_ui |= ...` 这一行报 `'x' is used uninitialized`：按 `uint64_t` 读的那块内存，在它看来从没被写过。隔一个函数就出错了：

```cpp
double alias(double* d, uint64_t* u) {
    *d = 1.0;
    *u = 0;          // 编译器认为 u 和 d 指的不是同一个对象
    return *d;       // 所以直接返回 1.0，不重新读
}
```

```text
alias(double*, unsigned long long*):
    movsd   .LC0(%rip), %xmm0    # .LC0 = 1.0
    movsd   %xmm0, (%rdi)
    movq    $0, (%rsi)
    ret
```

`alias(&x, (uint64_t*)&x)` 实测返回 1，内存里已经是 0；`-fno-strict-aliasing` 或 `-O0` 下返回 0。

源 :18 的 union 双关：C 允许，C++ 里读的不是最后写入的成员是未定义行为。GCC 文档明确支持通过 union 这样读（`-fstrict-aliasing` 的说明里），所以 GCC 上能用，换编译器不保证。

## 4. `memcpy` 与 `std::bit_cast`

把字节拷进目标类型的变量。固定 8 字节的拷贝编译器认得：`memcpy(&u, &x, 8)` 和 `std::bit_cast<uint64_t>(x)`（源 :35）都编成一条 `movq %xmm0, %rax`。`std::bit_cast` 还在编译期检查两边一样大、都能按字节拷贝，能用在 `constexpr` 里。

从收包缓冲区读字段也用 `memcpy`：`double read_px(const unsigned char* p)` 编成一条 `movsd (%rdi), %xmm0`，地址不对齐也行（实测从第 3 个字节读）；写成 `*(double*)p` 是违反严格别名，不对齐时还多一层未定义行为。x86 是小端；按大端发整数的协议（如 Nasdaq ITCH）读出来要翻转字节序，C++23 的 `std::byteswap` 编成一条 `bswap`。

## 5. union 的另一种用法：`std::variant`

源 :30 把 `std::variant` 叫作“安全替代方案（内存优化场景）”：它替代的是 union 的另一种用法，一块地方放几种类型之一（比如一条消息可能是新增订单、撤单或成交），不是用来转换位的。union 不记得现在放的是哪种，读错成员就又是双关；variant 多存一个下标：实测 `union { int; float; std::array<char,16>; }` 是 16 字节，同样三种类型的 variant 是 20 字节（1 字节下标，按 4 字节对齐补齐）。`std::get<int>` 类型不对时抛 `std::bad_variant_access`（实测）。源 :47 的 `std::visit` 编出来是读下标、比较、跳分支：`std::variant<int, float, double>` 实测一条 `movzbl` 加两次 `cmp`，和手写 `switch` 一样，没有虚函数调用。
